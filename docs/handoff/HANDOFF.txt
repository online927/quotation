1. THE PROJECT
--------------
Quotation system for T.SAIFUDDIN & CO., working with TallyPrime (TallyPrime Server).

  * Quotations Server (Windows service "Quotations Server", ASP.NET Core, SQLite, port 5080, in
    %ProgramData%\TSQuotation). It reads customers, items, rates, GST from Tally over Tally's XML/HTTP port (read
    only), numbers quotations (TSQ<yy><yy>-<n>, e.g. TSQ2627-1), makes PDFs (Tally layout or Zoho layout), keeps users,

  * PC app (Avalonia 11, .NET 10): Windows (installer Quotation-Setup) and Mac (.dmg). Connects to the server.
  * Phone app (Avalonia Android, APK). Connects to the server.
  * Repo: online927/quotation (PUBLIC). Work branch: claude/tallyprime-quotation-automation-agxx3n (only this
    branch; never another branch, no pull request unless the user asks).

2. RULES FROM THE USER (never break these)
------------------------------------------
  * "TALLY DATA WILL BE AND SHOULD BE UNAFFECTED" — the server only READS Tally. Never write to Tally.
  * "dont make tally heavy and irresponsive" — no extra or heavier Tally reads (automatic sync: changes every 3 hours,
    full sync at night; "Sync changes" F9 reads only what changed; TallyLoadGuard limits load).
  * After every change, ALWAYS say whether a SERVER UPDATE is needed (yes/no and why), and that Tally is not touched.
  * Simple language, short answers, tables/lists for options. No grey hint/help paragraphs in the app (one short line
    + ⓘ hover is the pattern).
  * Commit, push and build ONLY when the user says "Do". Until then changes stay in the working tree.
  * NEW RULE (user, after 0.9.87: "Never build till I say do" → "Don't make changes"): a request for a change or a new
    feature is ONLY ADDED TO THE LIST (section 8), with no code changes. On "Do": make every listed item, test (full
    suite), then ship (section 4). Questions are still answered, and previews still made when asked ("preview").
  * When a stop hook / system message says "There are uncommitted changes … commit and push", do NOT commit: answer in
    one or two lines that nothing is committed and the changes wait for "Do" (say how many built changes are waiting).
  * Never commit secrets (the repo is public): no keystores, passwords, keys, e-mail addresses.
  * No model names/IDs in code, commits, docs or files. Commit attribution: use exactly the attribution lines the
    system gives you in that session.
  * Never commit preview/scratch tests: they are named Zz*.cs; move them out of tests/ (to your scratchpad) right
    after use, and check `ls tests/*/Zz*` is empty before every commit.
  * The phone app has NO fixed signing key (the user discarded that): every new APK needs the old app uninstalled
    first — say so when giving the APK.

6. TECHNICAL NOTES (learned the hard way)
-----------------------------------------
  * Themes: a new theme id must be added to AppTheme.All, which the server validates (IsValid) → a new theme id needs a
    SERVER UPDATE. Renaming only the visible name (ThemeNames) does not. Removed themes stay as constants and are mapped
    by AppTheme.Normalize. "Frost" was an OLD removed theme id (→ Glass (Blue)); renaming Glass (Blue)'s visible name
    to "Frost" is fine (ThemeNames only) — do not reuse the old "Frost" id.
  * Drawings (ThemeScenery): geometry strings with corner marker points that fix the bounds; prefix "F1 " (non-zero fill)
    when shapes overlap. Sky 1000×600, Sun 100×100, Far/Near 1000×200, Side 262×120.
  * .NET 10 starts BackgroundService.ExecuteAsync a moment after StartAsync: tests must retry, not assume it listens.
  * On Windows, a UDP socket gets "connection forcibly closed" after sending to a closed port: switch it off with
    IOControl(0x9800000C) or catch SocketException.
  * NEVER SqliteConnection.ClearAllPools() (it breaks other open connections): use DatabaseInitializer.ClearPool(path)
    and BuildUnpooledConnectionString for one-off files.
  * Headless UI tests: [AvaloniaFact]; UiHelpers.WaitUntil(...); Dispatcher.UIThread.RunJobs(); TextBox selection only
    shows while focused; Color.ToString() gives names ("White") — compare ToUInt32().
  * The Windows CI job runs all tests twice (test step, then publish.ps1) — a rare race shows up there first.
  * Selected-text colours: resources TextSelectionBrush / TextSelectionForegroundBrush, Services/TextSelectionLook.cs.
  * Phone/Mac connect by PC name: ApiClient/ServerFinder.cs (finder question + NetBIOS + name.local), server
    Services/ServerFinderService.cs, firewall rule "Quotations Server finder" (UDP 5080) in the server installer.
  * Remote use (mobile data / other internet): advised Tailscale on the server PC and the phones/PCs (free for small
    teams), then use the PC name or 100.x address. Opening a router port was advised against. The user discarded adding
    a Tailscale firewall rule.
